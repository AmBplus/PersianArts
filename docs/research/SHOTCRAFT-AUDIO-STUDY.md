## 1. Original method, step by step
**Core fact first:** the shipped Ink Press template is SFX-only (TEMPLATE.md:6, Main.tsx:124 "no music bed"). Zero BGM code exists in the repo. The BGM method below is documentation, not code. All gallery card previews are silent (`muted: true` in workbench/scripts/render-demos.mjs:93 and check-demo.mjs:127); no demo contains `<Audio>`.

1. **Selection (music first when the user supplies it; otherwise stage 6).** Pick a strong-drum electronic bed, "typical product-promo", not "nice" (S1). Candidate must be laid under the actual cut and auditioned there ("single listening cannot judge a track"). History: Inspired (ambient piano) rejected, then Life of Riley (folk-pop, "too gamey"), then Mixkit tech-house, final in 34 min. Self-check: eyes closed, does it sound like a launch trailer or a phone game?
2. **Analysis (music-beat-sync.md).** librosa beat_track(tightness=400), then least-squares line fit t_i = t0 + i*T over the whole beat list (never trust the tempo scalar; 129.2 reported vs 131.97 true). Residual must be within +-15 ms. Test 0.5x/1x/2x grids. Drums-heavy or vocal tracks: hpss, else Demucs `--two-stems=drums -n htdemucs`. Hit classes: kick 40-160 Hz, snare 150-500 Hz body plus 1-3 kHz, hihat 6-14 kHz (butter order 4, onset_strength). RMS curve gives the **music structure table** (full-energy beat, breakdown beat) and a **top-2-3 strongest-hit list**.
3. **Grid acceptance, before any storyboard:** match >= 98 %, mean_abs < 10 ms, cumulative drift < 5 ms, beat 0 on a real attack; all candidates and the winning reason go to analysis/beat_data.json + grid_drift.json (+ optional click_*.wav). Floats in seconds, round to frames only in `beatF(n)=round((SOURCE_BEAT0+OUTPUT_AUDIO_OFFSET_SEC+n*T)*30)`.
4. **Timeline written in beats:** shots 4 or 8 beats long, boundaries = beatF(integer); dense cuts on grid, sparse accents and the final hold pinned to the **real transient** (a slam pinned at b52.5 while the kick was on b52 was +5.75 f late). Breakdown = brand breathing room. Full-frame impacts (scale pump, shake, flash, negative frame): **<= 3 per film, one per top hit, >= 16 beats apart**; beat-pump <= 4 beats once; everything else moves only the hero element (R4: users complained of "camera shaking with the music"). Hold budget: wordmark >= 30 f, batch finish 15 f still.
5. **Picture lock, then sound** (S3: three full SFX re-pins, two caused by picture changes). SFX = declarative table `{from, src, volume}[]`, each line commented with the picture action, wrapped in `<Sequence from durationInFrames>`. `from` must be relative (`SHOTS.x.from+offset` / `beatF(n)`), never bare frames (the template itself violates this, absolute frames). Palette: whoosh (camera), impact (landing), riser (build), sparkle (dir `light/`), transition; real-object foley (shutter, switch, glass, paper, keyboard). Forbidden: synth pluck/bloop/confirm tones ("sounds like a game"). Restraint: with a dense drum bed SFX mark only picture-unique actions, big slams 2-3.
6. **Levels:** BGM `interpolate(frame,[0,30,TOTAL-50,TOTAL],[0,0.34,0.34,0])` (1 s in, 1.7 s out); BGM peaks near 0 dB so 0.34 = about -9.4 dB. SFX volume 0.2-0.6 (click-camera 0.6, impact 0.55 = loudest; pop run 0.40/0.37/0.34/0.31/0.28/0.25) valid only for files peaking near 0 dB; 7 files peak < -12 dB (data-load-os -24.6 ... clock-tick-single -13.9) need swap, `loudnorm=I=-16:TP=-1.5` pre-norm, or volume > 1 (preview clamps to 1.0). Check with `ffmpeg -af volumedetect | grep max_volume` on the render. 21 samples > 5 s need explicit durationInFrames (keyboard 24 f / 44 f; default 90 f). Anti-machine-gun: alternate two *different* samples (4 library pairs are byte-identical, do not use as pairs), step volume down, accelerate spacing, or fade into one swoosh. Finale phrase: riser-cine at assembly start, **+35 f** impact-deep-whoosh (stamp, loudest), **+25 f** sparkle.
7. **Offset compensation (S5):** `from = targetPeakF - sourcePeakLagF - OUTPUT_AUDIO_OFFSET_F`. Measured AAC priming in this pipeline = 1.28 f @30 fps (2048 samples @48 kHz; method: extract `-acodec pcm_s16le`, normalised cross-correlation of 2-3 sharp SFX, consistent residuals). Per-file peak lag measured (brush-write 2 f, paper-slide 10 f, ink-char 24 f). Re-measure; acceptance residual <= 0.5 f. Durations are not offset.
8. **Render and verify:** two renders from one timeline: `promo.mp4` and `promo-nobgm.mp4` via `--props=props-nobgm.json` containing `{"bgm":false}` (not ffmpeg stem removal). Independent subagent review with final-review.md A1-A9 (A1 BGM leaves SFX headroom, A3 beat cuts <= 3 f, A4 riser/impact/sparkle, A5 long samples cut, A6 audible in the *render*, A7 UI sounds are real objects, A8 both versions frame-identical, A9 offsets measured and logged). **Post-render backtest:** re-fit the grid on the audio extracted from the final mp4; table design frame vs nearest measured beat: pass <= 3 f, ideal <= 1.5 f; audio-truth error mean < 5 ms, all within 33 ms, 90 % within 15 ms; 30 fps quantisation is +-16.7 ms and must not be claimed as < 5 ms. Same-sign errors = output offset, fix the constant, not each cut.

## 3. Upstream audio tools (all are doc snippets, none ships as a script)
- Beat fit/classify: inline Python in music-beat-sync.md run as `uv run --with librosa --with scipy --python 3.11 script.py` (Demucs: `uvx --from demucs demucs --two-stems=drums -n htdemucs bgm.mp3 -o analysis/`; madmom/Essentia as 2nd/3rd vote).
- Peak/offset: `ffmpeg -af volumedetect`; `ffmpeg -i out.mp4 -vn -acodec pcm_s16le x.wav` + numpy cross-correlation; dedupe `find assets/audio -name '*.mp3' -exec md5 -r {} \; | sort | awk '{print $1}' | uniq -d`; ATTRIBUTION/disk consistency `comm` one-liner (AUDITION md).
- Workbench: manifest `sfx[]`/`bgm[]` = `{from,duration?,src,volume,label?}` (default 90 f); projectImport.ts:84-85 packs them greedily into non-overlapping "Music"/"SFX" tracks; audio-clip card = Remotion `<Audio trimBefore playbackRate volume>` with volume slider 0-1 (cannot exceed 1); public/sfxlib and bgmlib link to assets/audio; gen-index.mjs lists them. No fades, no ducking, no waveform. JianYing export (jianying-export/aifl_promo.py, AUDIO_LAG_F = 1): SFX on greedy-packed lanes, BGM single segment at volume **0.72** (a different level from 0.34, unexplained).

## 4. Upstream gaps
No `bgm` inputProp or `<Audio>` for BGM in template (documented in 4 places, absent in code); no beat_data/grid_drift generator script; no fade/envelope code; no ducking (the words "Improved SFX ducking" and "-14 LUFS" appear only as fake UI text in demos); no master loudness target (only a SFX pre-norm example); template SFX uses absolute frames and ignores the S5 offset constants it documents; no shipped post-render backtest tool; audition rejection reasons lost; BGM files have no sidecar (sections/energy/safe cuts); no guidance for edit-shortening a track (the method assumes track length >= film); nothing for loops or 3-8 s clips. The 38 s gallery intro's audio source is not in the repo.

## 5. Our divergences, ranked by likely damage to "patched / poor"
1. **Synthesised music and SFX instead of recorded ones.** make_sound.py/synth.py build music from numpy saws/Karplus-Strong/noise (spec: "no stock audio"). Upstream's entire taste rule S1 is "real produced bed + real-object foley, never synthetic tones". Synthetic timbre is the most probable root of "poor". Dana bank also reuses samples cut from card videos (upstream render scripts mute card videos, so these may be near-silent or ours; unverified locally).
2. **Music is generated or looked up per clip, after the picture, and chased onto it.** Spec snaps tempo (+-4 %) and offset to the strongest picture cue; 4.5 s clips get a "sting" with a bar structure that cannot be heard as music. Upstream inverts: track first, picture cut to beatF grid. In the shipped library the 33 shotcraft previews carry **4 distinct beds** (md5 groups 17/6/6/4, keyed by `archetype`: cursorui/chart/particles/cameramove/skeleton share one), i.e. the bed is a lookup, not a choice made against that picture; 17 different cuts share the same 4.5 s loop; LRA 2.0 LU = no arc.
3. **Splicing (Dana v3.1):** 5 segments from 2 tracks, 0.5 s equal-power crossfades, RMS-matching, plus tanh soft-clip. Upstream: one track, fades only at head/tail. Cuts were set on measured hits (good) but joins are by RMS, not key/phrase/bar.
4. **Cues from motion energy, up to 16 per clip, all classified as whoosh/tick/pop.** Upstream: authored table per picture action, restraint under a drum bed, 2-3 slams, 0.9 SFX/s only because the film has no BGM. Ours: 7 cues in 4.5 s plus a drum kit plus a pad is dense with no hierarchy.
5. **No grid acceptance and no render backtest.** Spec section 4 checks LUFS, duration, and "sound onset within 25 ms of our own cue" (self-referential). Nothing measures cuts vs music beats in the final mp4; verify_sound.py, batch.py, test_sound.py, README listed in the spec/order are not in scripts/persian-sound/ (only analysis, io_utils, make_sound, mix, synth, profiles.json, 2 tests).
6. **No output offset compensation** (AAC 96 k @44.1 kHz priming about 1-1.4 f) and no per-file peak lag.
7. Not causes: loudness (-14.1 LUFS, TP -2.5 measured), and ducking (we have 2.5 dB; upstream none).

## 6. Recommendations
**Adopt verbatim:** music-first order and "iron rule: no storyboard before grid acceptance"; the 4 grid gates (98 % / 10 ms / 5 ms / first-beat); lstsq fit + 0.5x/1x/2x test; kick/snare/hihat bands; beat-denominated timeline (`beatF`); <= 3 full-frame hits, >= 16 beats apart; one track per film with head/tail fades (1 s / 1.7 s, 0.34 base) and a no-BGM twin from the same timeline; relative `from` expressions; S1 (real foley, ui/ files vetted by the 3.3 table); S5 formula; A1-A9; pre-norm or swap for the 7 quiet SFX; copy the shipped 11 template SFX + riser/impact/sparkle phrase as the default Persian palette.
**Change policy:** stop synthesising beds. Use real licensed tracks (the 5 upstream beds for energetic, Pixabay/Mixkit for Persian colour) cut by phrase; for 3-8 s card previews use either silence/SFX-only (as upstream's own sample films) or a bar-aligned 2- or 4-bar slice of a real loop, never an archetype lookup.
**Tools to add (so an agent decides on measurement):**
1. `music_map.py`: beat_data.json + sections + energy-per-bar + top-3 hits + safe_cuts for every library track (sidecar JSON), run once at ingest.
2. `grid_accept.py`: the four gates, prints PASS/FAIL and writes grid_drift.json.
3. `cut_check.py`: edit decision list of a film in seconds -> verifies every cut/join lies on a downbeat of both sides, same section type for crossfades, crossfade <= 1 beat, flags key/tempo mismatch (would have rejected Dana v3.1's joins).
4. `backtest_render.py`: extract audio from the final mp4, refit grid, compare picture event frames (from shots/SFX table) vs nearest beat, report offset separately, fail > 3 f; measures output-offset constant by cross-correlation.
5. `mix_sfx.py`: renders SFX table onto bed with sidechain/auto-duck (-3..-6 dB under impacts, 150 ms release), per-file peak normalisation, crowding report (SFX/s, simultaneous layers).
6. `ab_page` (artifact): same cut with bed A/B/no-bed and SFX on/off toggles, grid overlay, waveform with cue markers, for the owner's ear (the final authority).
